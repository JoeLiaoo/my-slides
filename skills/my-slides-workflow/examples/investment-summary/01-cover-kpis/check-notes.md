# 检查备注

## 期望通过的结构检查（`slides check`）

- 单元 ID 一致：`cover-kpis`，与 `units.json` 中的 ID 一致。
- 页面角色一致：`cover`，与单元一致。
- `slide-notes` 存在且为 JSON 对象，包含 verdict、main_risk、next_step、as_of。
- `mls-lucide-spec` 包含 `trending-up` 和 `shield-alert`，与 Spec「图标需求」一致。
- 自定义样式（如果加入 `<style>`）括号配对；本页只用了 `class`，无需 `<style>`。

## 期望通过的视觉自检（视觉规则 / 视觉规则 12 条）

- 一页一个结论：标题直接写「跟投 2 亿元」。
- 字号档位：标题 40 px、卡片数值 28 px、卡片标签 14 px、脚注 12 px；最大与最小 ≥ 1.5x。
- 数字带单位、日期、来源：脚注行写明日期、货币、来源。
- 关系类型与主视觉一致：对比 + 风险 → 卡片网格 + 同色阶对比；非饼图。
- 阅读顺序：标题 → 估值 → 增速 → 回本 → 集中度 → 风险 → 脚注。
- 留白：卡片之间 16 px；卡片内 12 px。
- 图标来自 lucide 白名单；语义单一（`trending-up` 只表示增长、`shield-alert` 只表示风险）。

## 与视觉规则失败案例的对应

- 不属于「失败 A：一页塞太多结论」（每张卡片一个 KPI，标题先抛结论）。
- 不属于「失败 B：饼图做份额」（本页无份额图）。
- 不属于「失败 C：来源堆到页脚」（脚注行就近附在 KPI 网格下方）。
