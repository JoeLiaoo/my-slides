# Charts reference

Open when picking a chart type or sanity-checking the numbers behind a page. Design+Slides has no chart library: draw charts as inline `<svg>` in the page (format limits in `<MY_SLIDES_DESIGN_ROOT>/skills/slides/references/format.md` §5), or import an image rendered elsewhere with `npm run slides:import-asset`.

## 数字与来源

图表数据须来自 `article.md` 或其中可核对的来源，并保留值、单位、期间、出处 URL 和估计口径。公开网络可用于补查市场规模、融资、ARR 或成本曲线等数字；先核实并更新正文，再写入页面。缺少可靠数字时记下证据缺口，不补造。仅在数字直接支撑本页结论时引用；无合适数字可用表格或结构图组织定性证据。数据变化时核对正文及所有受影响目标。

## 关系 → 图形

页面的关系类型决定主视觉（见 `references/slides.md` 的「写页前先想清楚」）。常用对应：

| 关系类型 | 推荐图形 | 关键字段 | 反例 / 避免 |
| --- | --- | --- | --- |
| 时间序列（趋势 / 拐点） | 折线 + 关键点注释 | 横轴时间、纵轴指标；标注关键年份 | 用柱状呈现连续趋势 |
| 结构构成（份额 / 占比） | 堆叠条（多组）或 100% 堆叠条 | 类别 + 数值；按合计或时间分组 | 单层饼图（难以比较类别之间） |
| 对比（横评 / 排序 / 敏感性） | 并列柱 / 哑铃图 / 双向条 / 表格 | 项目 + 两端值；或基期 + 情景 | 多系列折线堆在同一图 |
| 因果 / 流程（机理 / 漏斗） | 流程图 / 漏斗 | 步骤 + 转化率；流量方向 | 用饼图表达路径 |
| 风险 / 情景 | 矩阵 / 区间条 / 情景表 | 横轴风险维度、纵轴收益维度 | 用纯文字列出「高/中/低」 |

## 用内联 SVG 画图

1. 先定画图区宽高（通常 1664px 宽，留出标题和脚注），写 `width`、`height` 与同尺寸的 `viewBox`。
2. 定刻度映射，例如「0%–15% 对应 x = 260–1400，每 1% = 76px」，按它算每个点的坐标；把映射写在示例 README 或讲稿草稿里，方便日后改数。
3. 柱、条、瀑布用零基线；只标起点、终点、关键拐点和比较项需要的刻度。
4. 结论、副标题、来源写在 SVG **外面**的 `<h2>` / `<p>` 里：SVG 里的文字在编辑器里改不了，也不用 deck 字体。SVG 里只放坐标轴、类别名和数值标签，字号不小于 24px。
5. 写 `aria-label`，用一两句话说出单位和主要对比，不只重复标题。
6. 不写 `<script>`、`<foreignObject>`、事件属性或指向外部的 `href` / `url(…)`；源码不超过约 70 KB。
7. 颜色：一个强调色给结论相关的系列，其余用中性色；超过 4 个系列时合并成「其他」。

参考 `examples/competition/01-dumbbell/page.html`。

## 单位、口径与日期

- 单位写在刻度、图例或副标题里；不要让读者猜「亿还是万」。
- 日期口径（年化、月度、滚动）写在副标题或脚注。
- 同一张图里不混用口径；要比较时拆系列或拆图。
- 0 与负值要明确处理：负增长换颜色，缺失值在图上标出空缺。

## 数据 sanity-check

- 总和 vs 分项：堆叠条的合计是否等于各项之和？百分比堆叠每组是否合计 100%？
- 时间轴：类别是否按时间严格递增，没有重复？
- 舍入：图上数字与表格、正文、讲稿是否一致？
- 坐标：每个点是否按同一映射算出？换数据后有没有漏改的点？
- 货币 / 汇率：跨币种对比写汇率假设。

## 边界

- 图中每一个数值都必须能追溯到正文或其来源；口径不一致的值不得进入图表。
- 不用 CDN、网上图片地址或外部字体文件；导入的图片走 `import-asset`。
- 视觉规则（字号、留白、对比）见 `references/visual-rules.md`。
