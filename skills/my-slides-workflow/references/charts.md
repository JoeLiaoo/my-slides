# Charts reference

Open when picking a chart type or sanity-checking the numbers behind a Spec page. Charts in `slides/pages/<id>.html` must be declared in the Spec's `展示内容` and rendered with `mls-echarts-spec` JSON blocks. Renderer is ECharts 6.1.0 (`my-slides renderer install`).

## 数字证据清单

报告组装后、撰写 Spec 前运行 `my-slides prepare evidence-research`。公开网络可用于查市场规模、融资、ARR、成本曲线等硬数字；将值、单位、期间、出处 URL 和估计/口径写入 `my-slides/research/numbers.md`，再运行 `my-slides validate evidence-research`。每条记录用稳定编号（如 `N-001`），来源名称写成 `机构或作者《标题》（日期）`。缺少可靠数字时继续研究并记下数据缺口，不要补造数字。

所有图表数据只能取自该文件的记录。仅在数字直接支撑本页结论时引用编号；同一个数字 ID 在整套 deck 只能出现一次。无合适数字时允许无数字页，可用表格或结构图组织定性证据。有 ECharts 块时，必须在展示内容写 `数据编号：N-001`。图表 JSON 中的值、单位和期间应与对应记录一致。数据更新后先更新清单，再更新 Spec 并重新审批。准备图表时禁止从未登记的报告段落、访谈记忆或网页临时复制数字。

## 关系 → 图形

Spec「布局意图」中写的关系类型决定主视觉。常用对应：

| 关系类型 | 推荐图形 | 关键字段 | 反例 / 避免 |
| --- | --- | --- | --- |
| 时间序列（趋势 / 拐点） | 折线 + 关键点注释 | 横轴时间、纵轴指标；标注关键年份 | 用柱状呈现连续趋势 |
| 结构构成（份额 / 占比） | 堆叠条（多组）或 100% 堆叠条 | 类别 + 数值；按合计或时间分组 | 单层饼图（难以比较类别之间） |
| 对比（横评 / 排序 / 敏感性） | 并列柱 / 哑铃图 / 双向条 | 项目 + 两端值；或基期 + 情景 | 多系列折线堆在同一图 |
| 因果 / 流程（机理 / 漏斗） | 漏斗 / 流程图 / 桑基 | 步骤 + 转化率；流量方向 | 用饼图表达路径 |
| 空间 / 地理 | 简化地图 / 区域热力图 | 区域 + 指标 | 用国家形状代表占比 |
| 风险 / 情景 | 散点 / 矩阵气泡 / 误差条 | 横轴（风险维度）、纵轴（收益维度） | 用纯文字列出「高/中/低」 |

## 选择流程

1. 先回到「布局意图 → 关系类型」一栏，写下关系标签。
2. 在上表中找对应主图形；保留一个备选。
3. 在 Spec「展示内容」里写明字段、单位、`numbers.md` 数据编号和来源；图表数据要贴近结论而不是装饰。
4. 决定哪些刻度必须出现：起点、终点、关键拐点 / 比较项；其它刻度让 ECharts 默认。
5. 颜色：默认使用项目主题色；超过 4 个系列时合并成「其他」类别。
6. 检查视口：手机视口下避免双轴或 5+ 系列；多图横排时给每图留足够宽度。

## 单位、口径与日期

- 单位写在刻度或图例；不要让读者猜「亿还是万」。
- 日期口径（年化、月度、滚动）写在图标题或脚注。
- 同一张图里不要混用不同口径；要做比较时显式换坐标轴或拆分系列。
- 数字 0 与负值需要明确处理：占比 0 是否要单独标出？负增长是否要在轴上分色？

## 数据 sanity-check

提交 Spec 前过一遍：

- 总和 vs 分项：堆叠条的合计是否等于各项之和？
- 同比环比：增长率是否写在原始数之后？
- 舍入：图表上数字与表格数字是否一致？
- 缺失值：是否在图上明确标出空值或缺失区间？
- 货币 / 汇率：跨币种对比要写汇率假设。

## 可选页内 metric 绑定

在同一 Spec 页的展示内容中可以加一个 `metric-spec` JSON 块：

```metric-spec
{"version":1,"metrics":[{"id":"revenue","value":12.5,"unit":"亿元","period":"2025","source":"wiki/finance.md","scope":"示例口径"}]}
```

HTML 正文、KPI 和 slide-notes 字符串可写 `{{metric:revenue.value}}`、`.unit`、`.period`、`.source`、`.scope`，构建时从批准的本页 Spec 填入。单系列图表仍写完整值，并加 `"metricRefs":["revenue", ...]`（与 `values` 逐项对应）；数值和单位须与记录相同。跨页不能引用。修改数值、来源或口径会改变 Spec，须重新审批；旧 Spec 无须使用此块。未绑定的自然语言数值仍由人核对。

图表现在拒绝重复类别或系列名；时间折线可声明 `categoryKind: "time"`，类别必须按 ISO 日期严格递增；只有显式 `compositionPercent: true` 的百分比堆叠图才校验每组非负且合计 100%。瀑布图总计索引必须等于前面分项之和。柱状/堆叠/瀑布使用零基线；`axisMin`、`showLabels` 均可显式声明，隐藏标签须在图表旁保留可读数据与说明。图表 `summary` 会进入 SVG 可访问名称，描述单位和主要对比，不应只重复标题。

## 边界

- 图表数据写在 HTML 的 `mls-echarts-spec` 块里，且必须与 Spec「展示内容」一致；改数据就要重提 Spec。
- 图表中每一个数值都必须能追溯到 `research/numbers.md` 中的编号；没有编号或口径不一致的值不得进入图表。
- 不允许 CDN；ECharts 由本地渲染器提供。
- 视觉规则（字号、行长、留白、对比）见 `references/visual-rules.md`。
