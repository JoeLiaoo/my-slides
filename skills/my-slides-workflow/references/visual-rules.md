# Visual rules

Open before delivering HTML. These rules apply per page; `my-slides slides check` does not enforce them automatically — the agent catches them by reading the rendered slide and the Spec. The 12-point failure summary helps decide whether to fix a page or split it.

## 一、每页一个唯一结论

- 每页只为「一个结论」服务。结论写在 `核心结论` 字段里，并出现在页面顶部或底部的一句话。
- 如果 Spec 同时写了两个并列结论（如「公司增长快 + 估值便宜」），要么拆页、要么二选一。视觉上读者只读一个标题。
- 反例：一页同时出现「增长曲线」「市场份额饼图」「风险因素列表」，让读者自己拼结论。
- 修正：把次要结论放进脚注或单独一页；让主图占据 50% 以上视觉权重。
- 仅章节收束页和 Spec 标注的关键页显示「我们的判断 / 对投资的含义」作者结论框。嘉宾原话留在证据区，不让引用替作者下判断。
- 「估计」「未核验」「按某口径」等限定集中在来源脚注，一次交代清楚，正文保留简洁判断。

## 二、层级与字号档位

- 一页最多三档字号：标题、正文、脚注 / 来源。
- 同一层级内字号差异至少 1.5x（如标题 36px、正文 22px、脚注 14px）。
- 标题不要超过两行；超长标题拆成主标 + 副标。
- 桌面（1280×720）与手机（375×667）视口都要满足上面的对比度；不要为了适配手机而无限制缩小标题。

## 三、数字、单位、日期、来源贴近结论

- 每个关键数字旁带单位（亿元 / % / 万 / 倍）。
- 日期口径写在数字附近或脚注第一行。
- 来源写在数字附近的脚注，不要堆在页面最底部。
- 反例：所有数据来源集中放到页面最下方「参考资料」一栏。
- 修正：在图注或行内写出「来源：公司年报 / 招股书 P12」。
- 外部来源用一行统一格式：`机构或作者《标题》（日期）`；估计和口径紧接该来源说明一次。
- 图表数字必须对应 `my-slides/research/numbers.md` 的编号，页面中标出对应来源。研究清单未收录的数字不能用于图表。

## 四、先拆页，再缩字号

- 当一页信息装不下时：先拆页或删条目，再考虑缩字号。
- 正文最小不低于 14px（桌面）、12px（手机）。
- 反例：把 12 条要点挤在一页，正文压到 10px。
- 修正：拆成两页（如「前 6 客户」「后 6 客户」），或在每页放 4–6 条要点。

## 五、字体与行长阈值（视口 + 文本角色）

不要按「一页最多 N 字」一刀切。按视口和文本角色给阈值：

| 视口 | 标题字号 | 正文字号 | 脚注字号 | 单行字数（中文） | 单行字数（英文） |
| --- | --- | --- | --- | --- | --- |
| 桌面 1280×720 | 36–44 px | 22–28 px | 14–16 px | 18–22 字 | 60–80 字符 |
| 平板 1024×768 | 32–40 px | 20–26 px | 14–16 px | 16–20 字 | 50–70 字符 |
| 手机 375×667 | 24–30 px | 16–20 px | 12–14 px | 12–14 字 | 40–55 字符 |

- 标题允许换行但不超过 2 行；正文单段不超过 6 行。
- 表格列名至少与正文同档；数据列可以小一号但不能低于脚注。
- 同一段内不要混用「正文 + 注释 + 来源」三种字号。

## 六、关系类型与主视觉一致

- Spec「布局意图 → 关系类型」必须映射到主图形（见 `references/charts.md`）。
- 时间序列用折线；份额用堆叠条；对比用并列柱或哑铃；机理用漏斗；风险用矩阵。
- 反例：在「市场份额」上画饼图（难以比较份额变化）。
- 修正：换成 100% 堆叠条，并标出关键年份的份额变化。

## 七、阅读顺序与视线引导

- Spec「阅读顺序」里的 2–4 个停留点必须在页面上真实存在。
- 用字号、位置、留白形成阅读节奏，不要让读者到处找结论。
- 反例：标题在左上，关键数字在右下，结论句在中间；读者顺序混乱。
- 修正：让标题 → 主视觉 → 结论一句话形成左上 → 中部 → 右下 或 左上 → 左下 → 右下的连贯路径。

## 八、对比与重点

- 关键数字用色块、字号或位置突出；其余用低对比（细字、淡色）。
- 反例：所有数字都加粗 + 大字号，重点不明。
- 修正：保留 1–2 个数字走「高亮」处理，其它保持中性。

## 九、留白与对齐

- 元素四周留 ≥ 16px（桌面）/ 12px（手机）留白。
- 同一列内元素左对齐；不同列用横向位置对齐而不是字号。
- 不要让标题贴边或元素重叠。

## 十、图标与装饰

- 图标只用 lucide 白名单内的命名；不要用 emoji、表情、自制 SVG 图形代替。
- 一个图标只承载一个含义；不要给同一图标赋予两个标签。
- 反例：在「增长」图标里同时表达「增长」和「预期」。

## 十一、可重复构建（fixture）

- Spec 中的图表数据必须能从一个最小数据集复现；不要让示例页依赖不可重现的随机数。
- 示例 fixture 写在一个独立目录（如 `examples/<类别>/<id>/data.json`），所有页面里只引用它，不在 HTML 里写散落数字。
- 这样别人可以 `cp -r examples/<类别>/<id>` 直接复现。

## 十二、自查清单（交付前过一遍）

- [ ] 一页只承载一个结论
- [ ] 标题、正文、脚注三档字号，最大与最小 ≥ 1.5x
- [ ] 数字带单位、日期口径、来源
- [ ] 没把信息塞满而是拆页
- [ ] 关系类型 → 主视觉对应
- [ ] 阅读顺序与停留点存在
- [ ] 关键数字被突出
- [ ] 元素留白 ≥ 12px
- [ ] 图标来自 lucide 白名单且语义单一
- [ ] fixture 数据可独立复现

## 版式多样性与单页信息密度评分

每次 `review spec` 和 `slides visual-review` 都要逐页检查，并记录两个 1–5 分分数及一句证据。使用《开源破局》作为编辑参照：页面以清楚的主张为中心，文字、图表与结构关系共同承担论证；密度来自相关信息的组织，不来自重复数字或装饰元素。

### 版式多样性（deck 级）

- **5**：版式服务于内容类型；时间、比较、列表/矩阵、趋势、案例、收束使用明显不同且合适的结构；无超过两页的同版式连排。
- **4**：有清楚的版式节奏，少数相似页但主视觉或阅读路径不同。
- **3**：版式种类达到 validator 下限，部分相邻页仍像同一模板。
- **2**：大半 deck 重复同一结构，或版式与内容关系不匹配。
- **1**：几乎每页复用同一模板，读者无法从结构判断页面任务。

### 单页信息密度（逐页）

- **5**：一条明确结论；主视觉承载关键证据；相关的次级信息在表格/图示中紧凑分组，阅读顺序清楚，仍有足够留白。
- **4**：结论和证据紧密对应，信息充分且易扫读；局部可以再精简。
- **3**：信息可读，主次略平，或少量内容与结论关联较弱。
- **2**：页面偏空或拥挤；证据孤立、重复，读者需自行拼接关系。
- **1**：一页混合多个无关结论、数字重复凑数或文字/图表挤到难以阅读。

交付建议：deck 版式多样性至少 3 分，每页密度至少 3 分；任一页低于 3 分先调整结构、删减或拆页，再复审。数字 ID 每套 deck 只在最能支撑结论的一页出现一次；不适用数字时用结构图/表格，不造数。

## 最小失败 / 修正示例

### 失败 A：一页塞太多结论

```text
# 反例
同一页放：「近 5 年收入增长」「市场份额饼图」「Top 5 客户清单」「风险因素」。
字号压到 12px，标题被改成 20px 才能挤下；脚注只留 8px。
读者在 5 秒内找不到结论。
```

```text
# 修正
拆成三页：增长（折线 + 拐点标注）、份额（堆叠条 + 同比变化）、客户集中度（Top 5 表格 + 占比）。
每页一个主图、一个结论句；字号回到 36/22/14。
```

### 失败 B：饼图做市场份额

```text
# 反例
用饼图比较 2022 vs 2023 行业份额；两图并列，颜色相近，读者无法比较占比变化。
```

```text
# 修正
换成 100% 堆叠条，按年份分组；每条标注关键类别百分比，变化超过 2pp 的类别加箭头注释。
```

### 失败 C：来源堆到页脚

```text
# 反例
「数据来源：年报、招股书、调研」一行放在页面最下方；正文里所有数字都没有具体页码或日期。
```

```text
# 修正
每个数据点旁注脚：脚注 1 = 招股书 P12；脚注 2 = 公司 2024 年报；脚注 3 = 内部模型。
```

## 与工作流的连接

- Spec 阶段：用「布局意图」六个子项把规则 1–11 落到具体决策。
- HTML 阶段：写完后过一遍本参考的第十二条自查清单。
- 检视阶段（PR 2 / 联系单）：失败 A–C 的反例作为视觉 review 的最小复现页面。
