# Spec reference

Open when writing or validating a Spec page (`specs/units/<id>.md`). `my-slides validate spec` enforces the structure described here; pages that fail do not get approved.

## 文件结构

每份 Spec 由一个前置块和若干连续分页组成：

```text
# Spec：<小章节名>

单元 ID：<unit-id>
页面角色：cover | content

（前置块可写章节范围、阅读衔接、共享素材说明；不是必填。）

## Slide 1 — <页面标题>

### 目的
…

### 核心结论
…

内容类型：演进/时间线 | 对比 | 清单/矩阵 | 趋势/图表 | 案例 | 判断/收束
版式：从 `references/example-index.md` 的版式目录中选一项
关键页：是（可选；仅需作者判断框时填写）

### 我们的判断 / 对投资的含义
…（仅章节收束页或标注“关键页：是”时填写）

### 展示内容
…

### 证据与来源
…
需要数字时列出 `research/numbers.md` 中的编号（如 `数据编号：N-001`）；无合适数字时写明“无数字”，以表格或结构图组织信息。

### 限定条件
…
估计、未核验状态和数据口径在 HTML 来源脚注集中注明，正文不重复

### 报告段落映射
…

### 布局意图
#### 读者问题
…
#### 唯一结论
…
#### 关系类型
…
#### 主视觉
…
#### 阅读顺序
…
#### 选这个形式的原因
…

### 图标需求
- icon-name
（无图标时写「无」或 `- 无`，整段为空视为省略。）

### 来源脚注
机构或作者《标题》（日期）；估计/口径：一次性说明

## Slide 2 — <页面标题>
…
```

封面小章节只能一页；内容小章节最多八页。`单元 ID` 等于单元 ID；旧文件里的 `页面 ID` 仍可识别。`## Slide N — 标题` 编号必须从 1 连续递增。

## 每页必填小节

每一页都必须填齐以下小节；空小节会被 `validate spec` 拒绝。

| 小节 | 作用 | 内容提示 |
| --- | --- | --- |
| 目的 | 这页要为读者回答什么 | 一句话陈述读者视角的问题 |
| 核心结论 | 离开这页要带走的结论 | 一句话陈述该页唯一结论 |
| 内容类型 | 页面沟通任务 | 必须从顶部列出的六类中选一类 |
| 版式 | 页面结构 | 必须从 `references/example-index.md` 的版式目录中选一项 |
| 关键页 | 是否需要作者判断框 | 标注“是”时必填；章节收束（判断/收束）页也必填 |
| 我们的判断 / 对投资的含义 | 投资方作者的判断框 | 仅关键页和章节收束页填写；其他页删除此节 |
| 展示内容 | 在这页上能看到的具体元素 | 关键数据、对比项、图表、引用句 |
| 证据与来源 | 论据与可追溯资料 | 报告段落编号、Wiki 页面链接及 `numbers.md` 数据编号 |
| 限定条件 | 影响结论的边界 | 口径、估计、未核验状态等在脚注集中注明 |
| 报告段落映射 | 对应报告的哪一段 | 列出对应的小节或句子 |
| 布局意图 | 具体页面意图 | 见下方的「布局意图」六个子项 |
| 图标需求 | 需要的 lucide 图标 | kebab-case 名称（如 `chart-line`）；不需要时写「无」 |
| 来源脚注 | 页内一行来源 | `机构或作者《标题》（日期）`；估计/口径在此一次性说明 |

作者判断框只出现在标注“关键页：是”或内容类型为“判断/收束”的页面。嘉宾或外部专家的原话只能列入证据，不能代替投资方判断。每个数字 ID 在整套 deck 最多引用一次；无合适数字时允许无数字页，用表格或结构图组织信息。数字校验跨单元执行。

若本页声明 ECharts 图表，必须在 `展示内容` 中写 `数据编号：N-001`（可列多个编号）。图表的所有值只能来自这些清单记录，不得临时从报告、记忆或网页补数。`my-slides validate spec` 会检查编号存在、作者判断框、来源脚注格式及图表编号声明。

## 布局意图：六个子项

`布局意图` 是页面决策的具体视觉计划。每一页必须用六个三级子标题展开，缺一不可；任何一个子标题下为空都会被 `validate spec` 拒绝。这一步把页面决策从「口号」落到「读者一眼看到的主视觉 + 路径」。

### 读者问题

读者打开这页会问什么？一句话写出对方最想知道的事，例如「这家公司的客户集中在哪些行业」。这一项驱动其余五个子项。

### 唯一结论

读完这页后，读者唯一需要带走的结论是什么？例如「头部三家客户合计占 70% 收入，集中度风险显著」。结论必须能被一两个数字或一句对比句概括。

### 关系类型

这页表达的是什么关系？常见选项：

- 时间序列（趋势、拐点）
- 结构构成（份额、占比、堆叠）
- 对比（横评、列对比、敏感性）
- 因果 / 流程（机理、传导路径、漏斗）
- 空间 / 地理
- 风险 / 情景

写一个最贴近的标签，用于选择主视觉。

### 主视觉

这页用什么图或构图承载结论？给出具体类型和大致字段：

- 「折线 + 标注：横轴年份、纵轴份额、关键拐点注释」
- 「并列双柱 + 同行摘要：左列基期、右列预测期」
- 「堆叠条 + 占比标签：每条 = 客户类别」
- 「漏斗：环节 → 转化率 → 留存」
- 「矩阵气泡：横轴增速、纵轴毛利、气泡 = 公司」

不要写「合适的图」。要给到读者一眼能看到的元素与字段。

### 阅读顺序

视线从左上到右下的路径是什么？把页面分成 2–4 个停留点，按顺序写出，例如「先看标题 → 折线趋势 → 拐点注释 → 结论一句话」。如果有并列的两个图（如对比页），要说明读者先看左还是先看右。

### 选这个形式的原因

为什么这个形式比替代方案更能承载结论？一句话给出取舍，例如「堆叠条比饼图更容易比较行业间的份额变化，比折线更直观显示结构」。避免空话；要写出形式 vs 结论的耦合。

## 工作流

1. `my-slides prepare spec --unit <id>` → 在 `my-slides/work/specs/<id>.md` 得到交接材料（含单元 ID、章节、文件路径）。
2. 按本参考写出 `specs/units/<id>.md`；图标与图表声明直接进入本页的 `图标需求` 与 `展示内容`。
3. 先通过 `my-slides validate evidence-research`，再运行 `my-slides validate spec --unit <id>`：检查内容类型和版式、作者判断框条件、来源脚注、数字编号有效且全 deck 不重复、版式连续不超过两页且种类达到下限、布局意图六个子项均非空、`报告段落映射` 非空、单元 ID 与角色一致、图表/图标范围与本单元一致、本地 Markdown 链接全部解析。
4. `my-slides approve spec --unit <id>` 提交待审；`review` 输出 `APPROVE` / `REJECT` 短语；用户明确批准后 `confirm spec --via chat`。
5. 章节整体修改后只需重提该章节；其他章节仍按各自版本审批。

## 边界

- Spec 不写论证；论证放在 `reports/units/<id>.md`。
- Spec 不写 HTML；HTML 在 `slides/pages/<id>.html`。
- Spec 不写 deck 级封面（cover 单元自己就是封面）。
- 改名（`units retitle`）不触发 Spec 失效；改动 Spec 内容需要重新审批。
