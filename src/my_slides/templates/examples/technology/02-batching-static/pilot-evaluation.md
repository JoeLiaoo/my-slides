## 多视口实测（issue #38 收尾，2026-10-14 SGT）

在 main 主题外壳下用 `check_deck(..., evidence_dir=...)` 对两版各跑桌面 1920×1080、手机竖屏 390×844、横屏 844×390，并落盘 PNG、contact sheet 与 `measurements.json`。

| 版本 | 自动检查 | 视口表现（人工看图） |
| --- | --- | --- |
| `page.html`（静态 SVG） | `valid=true`，无 errors / warnings | 桌面显示五步 SVG 与收益/代价说明；竖屏隐藏 SVG、改有序列表；横屏为五列步骤。脚注以 `.note` 角色通过桌面 note 字号阈值。 |
| `text-only.html` | `valid=true`，无 errors / warnings | 三视口正文可读，无溢出/裁切/重叠。 |

证据目录（本机收尾产物，不进仓库）：`/workspace/pi-tasks/issue-38-closeout/{svg-pilot,text-only}/evidence/`。初检时 SVG 版桌面把 `.boundary` 判为 body（阈值 14px）而失败；加上 `note` 类后复测通过。

采用随机分配、盲问方式：3–5 位未参与制作的读者各看一个版本，回答：(1) 执行前新增了哪两步？(2) 可能的收益是什么？(3) 代价是什么？(4) 图中是否给出了实测加速幅度？记录耗时、错误和追问。每次修订记录实际工时与 QA 问题。样本很小，只用于决定是否值得再做受控扩展。

**当前决策：停在静态试点。** 多视口截图与自动可读性已测通；读者理解试验仍未做，因此不引入 figure-spec 或交互 runtime。若多次真实项目中相同图形重复出现、读者理解有明显收益，再单独设计受控、声明式 figure-spec，保持逐页批准数据匹配与 SVG 清理；交互另行验证静态首帧、焦点隔离、键盘、reduced-motion 与切页清理。
