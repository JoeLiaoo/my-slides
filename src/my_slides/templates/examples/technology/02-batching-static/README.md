# 静态解释图试点：推理请求的动态批处理

本例是概念性的流程解释，不含实测吞吐、时延或成本数字。受众需要理解为什么把同时到达的请求放在一个批次中可以提高设备利用率，以及等待队列引入的取舍。数据、Wiki 和公司均为虚构。

`page.html` 是源片段；`text-only.html` 是同一结论的文字对照。桌面展示静态 SVG，窄屏展示等价的有序步骤。图像从本页已批准 Spec 的步骤手工绘制；没有引入可执行脚本、figure-spec 或动态运行时。

## 适用边界

- 方框数、箭头长度和排列位置不表示真实比例或性能。
- 省略了连续批处理、prefill/decode 拆分、请求取消、缓存命中与调度优先级。
- 只有当 Spec 明确说明队列、成批执行和取舍时才复用这张图。

## 比较与停止条件

`pilot-evaluation.md` 记录两种版本的文件字节数、多视口截图实测、要回答的问题及评估方式。三视口浏览器检查与截图已在 #38 收尾完成；读者理解试验尚未做，不把设计假设写成实测理解优势。在真实项目中用 3–5 位未参与制作的读者分别阅读随机分配的版本，问「批处理前多了哪一步」「收益和代价各是什么」，记录答对率、完成时间与修改工时。只有理解收益明显且重复制作成本可接受，才考虑声明式 figure-spec；交互需另做焦点、静态首帧、停止和 reduced-motion 验证。
