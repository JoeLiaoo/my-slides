# 静态解释图：推理请求的动态批处理

本例是概念性的流程解释，不含实测吞吐、时延或成本数字。受众需要理解为什么把同时到达的请求放在一个批次中可以提高设备利用率，以及等待队列引入的取舍。正文和数据均为虚构。

`page.html` 用 Design 自带的形状（`<x-shape>`）、连线（`<x-connector>`）和钉住的文字（`<p style="position:absolute">`）画五步流程，而不是内联 SVG：这样每个方框里的字在 5173 编辑器里都能直接改，也会用 deck 的字体。图只从示例 `article.md` 的段落手工画出；没有可执行脚本、figure-spec 或动态运行时。

## 适用边界

- 方框数、箭头长度和排列位置不表示真实比例或性能。
- 省略了连续批处理、prefill/decode 拆分、请求取消、缓存命中与调度优先级。
- 只有当正文明确说明队列、成批执行和取舍时才复用这张图。

## 复用

五个方框等宽 260px、间隔 91px，连线落在方框垂直中线（y = 490）上。增减步骤时重算 `left` 与连线的 `x1`/`x2`；步骤超过 6 个就拆页，不要缩小字号。
