# My Slides：本地投资项目 Wiki 与报告生成工具

## 产品目标与流程

在任意本地投资项目目录中，使用当前的 Codex、Claude Code 或 DeepSeek harness 调用统一 CLI，完成：

**Markdown 资料 → 项目 Wiki → 完整投资报告 → 用户审阅 → 分章 Presentation Spec → 用户审阅 → 分章 HTML Slides → 合并整套。**

当前 agent 负责阅读、研究、写作和页面设计；工具负责资料索引、版本管理、引用检查、图表渲染、页面合并和质量检查。

第一版提供纯 Markdown Wiki、增量更新、按需联网研究和可调整的内置报告模板。文档转换由用户提前完成；第一版不包含 OCR、内置 agent 调度、网页知识工作台或 MCP 服务。

## 项目目录与 Wiki

工具全局安装，每个投资项目的数据保存在项目目录中：

```text
投资项目目录/
├── 原有资料及人工转换的 Markdown
└── my-slides/
    ├── project.yaml       # 资料范围、报告章节、视觉配置
    ├── research/          # 按需联网研究的来源记录
    ├── wiki/              # 知识页面、索引、来源、待核实问题
    ├── reports/           # 分章正文与审阅版本
    ├── specs/             # 分章分页与视觉规格
    ├── slides/            # 章节产物、整套 HTML、检查结果
    └── .state/            # 资料指纹、依赖关系、版本和审阅记录
```

初始化时默认扫描项目内 Markdown，排除工具产物、Git、依赖目录和 agent 指令文件；支持显式配置资料目录。原始资料保留在原位置。

Wiki 默认按公司、团队与股权、产品与技术、行业、竞争、商业进展、财务、融资与交易、风险与待核实事项组织。Agent 可以根据项目增加主题。每页包含摘要、事实与证据、分析判断、相关页面和来源；事实、判断和预测分别标明。

来源记录使用稳定资料 ID、内容版本和段落定位，保留原文件路径及必要摘录；若源 Markdown 提供页码，则一并记录。增量扫描识别新增、修改和删除，列出受影响的 Wiki 页面和报告章节。资料口径冲突进入待核实清单，并保留各来源日期和口径。Wiki 更新保留历史和人工编辑，不通过全量重建覆盖已有知识。

联网研究由当前 agent 按用户要求执行。研究结果先保存 URL、访问时间和支持结论的摘录，再纳入 Wiki。工具检查引用是否存在、是否仍匹配对应版本；内容准确性由 agent 和用户审阅。

## 投资报告与 Presentation Spec

内置中文 PE／IC 报告章节为：投资摘要、公司与团队、产品与技术、行业与市场、竞争与壁垒、商业化与客户、财务与预测、估值与交易方案、风险与尽调问题、投资建议与后续条件。项目可以增删章节和调整顺序。

报告撰写完整论证，保留证据、计算依据和重要限定条件；资料不足时明确列出缺口。正文引用具体 Wiki 版本，并可追溯到原始资料。每次生成保存独立版本，支持按章节修改。

用户确认报告后，agent 按章节生成 Markdown Spec，由工具解析并校验。每页包含页面 ID、所属章节、标题、目的、核心结论、展示正文、证据、必要限定条件、报告段落引用、布局意图，以及可选图表类型、数据、单位、来源和图标需求。

默认保留报告论证顺序，允许拆分或合并相邻内容，不设置固定页数上限。实质性报告段落必须映射到页面。全套 Slides 使用一个总封面和统一视觉配置。Spec 不增加报告之外的事实；定量图表数据须与批准的 Spec 一致。

正文及全部章节 Spec 各设一次用户审阅节点。agent 收到用户明确确认后，通过 CLI 将批准状态绑定到对应内容版本。正文或 Spec 改动会使对应批准状态失效，并将受影响的下游产物标记为待更新。新增资料会标出影响范围，历史批准版本和已交付 Slides 保留查看。

## CLI 与 agent 交接

使用 Python CLI 与 Node.js 渲染辅助程序。优先验收 Windows，路径兼容中文及空格；通过 `uv tool install .` 安装命令入口，并提供依赖安装和环境诊断。

核心命令分组：

| 命令 | 职责 |
| --- | --- |
| `my-slides init / doctor / status` | 初始化项目、检查环境、查看工作进度与失效状态 |
| `my-slides sources scan` | 更新资料索引，返回变化和影响范围 |
| `my-slides prepare wiki / report / spec / slides` | 准备阶段输入、写作指引及预期输出位置 |
| `my-slides validate wiki / report / spec` | 检查格式、引用、覆盖率及阶段依赖 |
| `my-slides approve report / spec` | 用户确认后绑定批准版本 |
| `my-slides slides build / check` | 渲染图表和图标、合并页面、运行质量检查 |

命令支持 `--project` 与 `--json`；默认从当前目录向上定位项目。`prepare` 提供交接材料，当前 agent 执行生成任务。提供统一工作流说明及可安装 skill；安装时不覆盖已有 `AGENTS.md` 或 `CLAUDE.md`。

## HTML Slides 与视觉实现

参考 `my-latent-space` 中 Article → Presentation Spec → HTML Slides 的流程，提取 Spec 校验、ECharts 配方、Lucide 展开和浏览器检查能力，去除原系统的服务端任务队列和模型路由依赖。

参考 [bluedusk/html-slides](https://github.com/bluedusk/html-slides) 的页面设计指导，为章节输出增加统一协议：agent 生成章节页面片段、章节作用域 CSS 和逐页备注；工具负责统一文档外壳、主题、连续页码、目录、键盘及触屏导航。章节片段不带独立导航脚本。校验跨章 CSS、重复元素 ID 和无效页面结构。每章可单独预览、重做和合并。

初始依赖沿用 `my-latent-space` 已固定的版本：`html-slides` 提交 `d8289f4c317905cc5d0ca265d32b791e6cb387b7`、ECharts `6.1.0`、`lucide-static` `1.52.0`。安装时校验版本，保留许可证与来源信息。

默认采用 1920×1080、16:9 浅色专业 IC 风格，深色文字，红色品牌色 `#A6192E`；颜色可按项目调整。正文通常至少 28px，辅助文字至少 20px。

定量图表使用 ECharts，首版支持条形图、点图、折线图、多折线、散点图、时间散点、堆叠条形图和瀑布图；表格使用 HTML。Agent 输出受限的数据标记，工具将图表生成并内联为 SVG。Lucide 依图标名称生成内联 SVG。最终成品为单个可离线打开的 HTML，包含 CSS、导航、图表、图标和备注；来源保留普通链接。

## 实施里程碑

1. **项目与 Wiki**：CLI、初始化、资料索引、来源协议、增量变化识别和 agent 工作流。
2. **报告与 Spec**：章节模板、交接材料、来源映射、两次审阅和版本失效机制。
3. **Slides**：红色主题、章节输出协议、ECharts／Lucide 渲染、整套合并和质量检查。
4. **端到端验收**：安装说明、示例项目、自动检查及真实 agent 试跑。

## 验收标准

- 覆盖中文路径、重复初始化、资料新增／修改／删除和人工 Wiki 编辑保留。
- 覆盖来源缺失、口径冲突、过期引用、报告段落遗漏及批准后内容改动。
- 覆盖单章重做、跨章样式隔离、连续导航、逐页备注与图表数据一致性。
- 缺失值不得自动填零；单位不兼容时拒绝绘图；无效图标或未展开标记应明确报错。
- 用 Playwright 检查桌面和手机视口中的溢出、重叠、文本可见性及导航；断网验证整套 HTML。
- 用合成投资项目和真实 agent 跑通完整流程，并逐页检查生成结果。自动化测试与真实生成验收分别记录。

完成标准：在新投资项目目录中，agent 可通过同一套命令完成资料建库、报告、Spec 和离线 Slides；报告与 Spec 的审阅状态正确绑定版本，关键结论可追溯，资料变化和章节修改可以局部更新。
