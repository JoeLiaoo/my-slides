# My Slides：本地投资项目 Wiki 与报告生成工具

## 产品目标与流程

在任意本地投资项目目录中，使用当前的 Codex、Claude Code 或 DeepSeek harness 调用统一 CLI，完成：

**Markdown 资料 → 项目 Wiki → 完整投资报告 → 用户审阅 → 分章 Presentation Spec → 用户审阅 → 分章 HTML Slides → 合并整套。**

当前 agent 负责阅读、研究、写作和页面设计；工具负责资料索引、版本管理、引用检查、图表渲染、页面合并和质量检查。

第一版提供纯 Markdown Wiki、增量更新、按需联网研究和可调整的内置报告模板。文档转换由用户提前完成；第一版不包含 OCR、内置 agent 调度、网页知识工作台或 MCP 服务。

## 项目目录与 Wiki

工具全局安装，每个投资项目的数据保存在项目目录中：

```text
投资项目目录/
├── 原有资料及人工转换的 Markdown
└── my-slides/
    ├── project.yaml       # 资料范围、报告章节、视觉配置
    ├── research/          # 按需联网研究的来源记录
    ├── wiki/
    │   ├── README.md      # 简短的 Wiki 维护约定
    │   ├── index.md       # 按 presentation 章节组织的页面索引
    │   ├── log.md         # 追加记录资料整理、研究与维护活动
    │   └── *.md           # 按实际需要创建的专题与综合分析页面
    ├── reports/           # 分章正文与审阅版本
    ├── specs/             # 分章分页与视觉规格
    ├── slides/            # 章节产物、整套 HTML、检查结果
    └── .state/            # 扫描指纹、内容快照和审阅记录
```

初始化时默认扫描项目内 Markdown，排除工具产物、Git、依赖目录和 agent 指令文件；支持显式配置资料目录。原始资料保留在原位置。

### 方法与页面组织

参考 [Andrej Karpathy 的 LLM Wiki 方法论](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：agent 将阅读和研究结果持续整理为相互链接的 Markdown 页面，新资料到来时更新相关页面，有价值的问答与综合分析也可以沉淀回 Wiki。原始资料、知识页面与维护约定分别存放。

本项目采用轻量实现：用户准备资料和提出研究问题，agent 负责阅读、综合、链接和维护，CLI 辅助扫描变化与检查链接。Wiki 使用自然语言和普通 Markdown，不要求 YAML frontmatter、标签体系、逐条“事实／判断／预测”分类或来源资料 ID。数字口径、预测假设、信息日期和不确定性在有必要时直接写入正文。

`wiki/README.md` 用简短文字约定资料范围、页面命名、链接方式，以及整理资料、回答问题和检查 Wiki 的步骤。内容页面围绕具体主题展开，按需使用标题、正文、表格、相关页面和参考资料链接；不强制统一字段或逐条证据登记。

### 按 presentation 章节导航

`wiki/index.md` 默认以 [投资报告章节模板](../templates/投资报告章节.md) 的六个一级章节为分组，顺序为：投资概要、公司概况、行业分析、业务情况、财务分析与回报分析、下一步工作计划。每组列出相关页面链接和一句话说明，必要时按模板中的下级标题或写作要点细分，帮助 agent 从目录找到写作材料。报告及 presentation 使用同一套章节导航。

章节名称和顺序以 `project.yaml` 的章节配置为准，调整章节后同步更新索引。同一专题页可以出现在多个章节下，知识正文只维护一份；尚未纳入汇报的研究页面可放在索引的“补充研究”分组。章节可以对应多张 Slides，索引不承担逐页排版职责。

### 整理、问答与维护

- **整理资料（ingest）**：阅读新增或变化的 Markdown，将信息融入相关专题页，按需创建资料摘要或综合分析，补充页面之间的链接，更新索引并在 `log.md` 追加简短记录。原始资料由 agent 只读。
- **问答与研究（query）**：先从索引定位页面，再综合回答并附上相关链接。值得长期保留的比较、推导或研究结论写回 Wiki，同时维护索引与日志。
- **检查维护（lint）**：工具检查断链、索引遗漏等可确定的问题；agent 阅读并处理过期内容、口径冲突、重复页面、缺少关联及研究缺口。问题用自然语言写在相关页面，需要集中跟进时再建立待核实页面。

来源使用可读的 Markdown 文件链接或网页链接，放在相关论述附近或参考资料中；需要精确定位时补充原文标题、页码或摘录。无需为资料分配人工维护的 ID，也不要求给每段知识附加版本字段。源文件改名或删除后检查链接，保留必要的来源说明并提示复核。

扫描指纹仅用于工具内部识别文件变化。扫描命令返回变化文件，agent 根据现有链接和章节索引复核可能受影响的页面及报告章节；第一版不建设独立的知识依赖图数据库。内容快照和审阅记录由工具在后台保存，Wiki 更新保留历史及人工编辑。

联网研究由当前 agent 按用户要求执行。研究结果在 `research/` 中保存简短 Markdown 笔记，附 URL、访问时间和必要摘录，再整理进 Wiki。内容准确性和引用是否支持结论由 agent 与用户复核。

## 投资报告与 Presentation Spec

默认报告结构以 [投资报告章节模板](../templates/投资报告章节.md) 为依据。初始化项目时，将模板的章节名称、顺序和写作要点载入项目配置，作为 Wiki 索引、报告及分章 Spec 的共同基础。项目可以增删章节和调整顺序，已配置项目的调整予以保留。

| 一级章节 | 下级结构与写作要点 |
| --- | --- |
| 投资概要 | 包含“投资摘要”“投资亮点”“投资风险”。投资摘要覆盖项目名称、项目来源、项目组成员、拟投基金、公司业务简介、财务数据摘要、交易架构、核心条款摘要、返投落地（如有）、退出方式、收益测算。 |
| 公司概况 | 工商信息、发展历程、融资历程、股权架构、团队介绍。 |
| 行业分析 | 行业发展介绍、需求分析、供给分析/竞争分析、政策分析、驱动力总结、市场规模测算。 |
| 业务情况 | 主营业务介绍、产品介绍、技术介绍、商业模式介绍、商业进展/在手订单。 |
| 财务分析与回报分析 | 利润表分析、资产负债表分析、现金流量表分析、估值对比、盈利预测、投资回报预测和敏感性分析。 |
| 下一步工作计划 | 提请事项、后续工作计划。 |

模板中的二级 Markdown 标题对应报告一级章节，三级标题对应章内小节，其余条目作为该章或小节的写作要点；这些要点不要求一项对应一页 Slides。“返投落地（如有）”按项目实际适用情况展开。资料不足的要点明确列出缺口，避免为填满模板补写无依据的信息。以上表格说明当前模板内容，后续默认模板维护以原 Markdown 文件为准。

报告撰写完整论证，保留证据、计算依据和重要限定条件；资料不足时明确列出缺口。Agent 按 Wiki 索引中的章节查阅相关页面，正文用普通链接引用 Wiki 或原始资料。工具在生成时保存所用 Wiki 页面快照，后台记录版本，不向 Wiki 正文增加资料 ID 或复杂元数据。每次报告生成保存独立版本，支持按章节修改。

用户确认报告后，agent 按项目配置中的章节顺序生成 Markdown Spec，默认对应模板的六个一级章节，由工具解析并校验。每页包含页面 ID、所属章节、标题、目的、核心结论、展示正文、证据、必要限定条件、报告段落引用、布局意图，以及可选图表类型、数据、单位、来源和图标需求。

默认保留报告论证顺序，允许拆分或合并相邻内容，不设置固定页数上限。实质性报告段落必须映射到页面。全套 Slides 使用一个总封面和统一视觉配置。Spec 不增加报告之外的事实；定量图表数据须与批准的 Spec 一致。

正文及全部章节 Spec 各设一次用户审阅节点。agent 收到用户明确确认后，通过 CLI 将批准状态绑定到对应内容版本。正文或 Spec 改动会使对应批准状态失效，并将受影响的下游产物标记为待更新。新增资料会标出影响范围，历史批准版本和已交付 Slides 保留查看。

## CLI 与 agent 交接

使用 Python CLI 与 Node.js 渲染辅助程序。优先验收 Windows，路径兼容中文及空格；通过 `uv tool install '.[browser]'` 安装命令入口，并提供渲染器依赖安装、Playwright Chromium 安装和环境诊断。

核心命令分组：

| 命令 | 职责 |
| --- | --- |
| `my-slides init / doctor / status` | 初始化项目、检查环境、查看工作进度与失效状态 |
| `my-slides sources scan` | 扫描资料变化，提供待整理文件；影响范围由 agent 结合链接与章节索引复核 |
| `my-slides prepare wiki / report / spec / slides` | 准备阶段输入、写作指引及预期输出位置 |
| `my-slides validate wiki / report / spec` | Wiki 检查链接与索引完整性；报告和 Spec 检查引用、覆盖率及阶段依赖 |
| `my-slides approve report / spec` | 用户确认后绑定批准版本 |
| `my-slides renderer install / doctor` | 安装并核验锁定版本的 ECharts 与 Lucide |
| `my-slides browser install / doctor` | 安装并核验 Playwright Chromium |
| `my-slides slides build / check --browser` | 渲染图表和图标、合并页面，并在桌面与手机视口运行质量检查 |

命令支持 `--project` 与 `--json`；默认从当前目录向上定位项目。`prepare` 提供交接材料，当前 agent 执行生成任务。Wiki 阶段的交接材料包括维护约定、章节索引、近期日志和待整理文件列表；问答与语义检查沿用同一套约定，由当前 agent 执行。提供统一工作流说明及项目级可安装 skill；安装时不覆盖已有同名技能或 `AGENTS.md`、`CLAUDE.md`。

## HTML Slides 与视觉实现

参考 `my-latent-space` 中 Article → Presentation Spec → HTML Slides 的流程，提取 Spec 校验、ECharts 配方、Lucide 展开和浏览器检查能力，去除原系统的服务端任务队列和模型路由依赖。

参考 [bluedusk/html-slides](https://github.com/bluedusk/html-slides) 的页面设计指导，为章节输出增加统一协议：agent 生成章节页面片段、章节作用域 CSS 和逐页备注；工具负责统一文档外壳、主题、连续页码、目录、键盘及触屏导航。章节片段不带独立导航脚本。校验跨章 CSS、重复元素 ID 和无效页面结构。每章可单独预览、重做和合并。

初始依赖沿用 `my-latent-space` 已固定的版本：`html-slides` 提交 `d8289f4c317905cc5d0ca265d32b791e6cb387b7`、ECharts `6.1.0`、`lucide-static` `1.52.0`。安装时校验版本，保留许可证与来源信息。

默认采用 1920×1080、16:9 浅色专业 IC 风格，深色文字，红色品牌色 `#A6192E`；颜色可按项目调整。正文通常至少 28px，辅助文字至少 20px。

定量图表使用 ECharts，首版支持条形图、点图、折线图、多折线、散点图、时间散点、堆叠条形图和瀑布图；表格使用 HTML。Agent 在已批准 Spec 中给出受限 JSON 图表数据，Slides 标记必须与 Spec 数据完全一致，工具将图表生成并内联为 SVG。Lucide 依图标名称生成内联 SVG；最终 HTML 附带所用软件的许可证与来源信息。最终成品为单个可离线打开的 HTML，包含 CSS、导航、图表、图标和备注；来源保留普通链接。

## 实施里程碑

1. **项目与 Wiki**：CLI、初始化、章节索引、普通来源链接、更新日志、增量变化识别和 ingest／query／lint 工作流。
2. **报告与 Spec**：章节模板、交接材料、来源映射、两次审阅和版本失效机制。
3. **Slides**：红色主题、章节输出协议、ECharts／Lucide 渲染、整套合并和质量检查。
4. **端到端验收**：安装说明、可复现的六章合成项目自动检查及浏览器验收；真实项目仍需逐页人工审阅。

## 验收标准

- 覆盖中文路径、重复初始化、资料新增／修改／删除和人工 Wiki 编辑保留。
- Wiki 在没有 frontmatter、分类标签、来源资料 ID 和逐段版本字段时仍能完成整理、问答及报告准备；来源可通过普通链接查阅。
- 索引按 presentation 章节导航；章节调整后同步更新，同一页面支持跨章引用，补充研究保持可发现。
- 默认 Wiki 索引、报告和分章 Spec 与投资报告章节模板的六章名称、顺序及下级写作要点一致；项目自定义调整可保留，条件性条目按适用情况处理，缺失资料明确列出。
- 新资料能更新已有页面和相关链接；有价值的问答可沉淀为页面；整理与维护活动追加日志，断链与语义问题分别由工具和 agent 检查。
- 覆盖来源缺失、口径冲突、过期引用、报告段落遗漏及批准后内容改动。
- 覆盖单章重做、跨章样式隔离、连续导航、逐页备注与图表数据一致性。
- 缺失值不得自动填零；单位不兼容时拒绝绘图；无效图标或未展开标记应明确报错。
- 用 Playwright 检查桌面和手机视口中的溢出、重叠、文本可见性及导航；断网验证整套 HTML。
- 用六章合成投资项目跑通完整流程，并逐页检查浏览器可测量的元素、文本和导航；自动化测试与真实项目的内容审阅分别记录。

完成标准：在新投资项目目录中，agent 可通过同一套命令完成资料建库、报告、Spec 和离线 Slides；报告与 Spec 的审阅状态正确绑定版本，关键结论可追溯，资料变化和章节修改可以局部更新。
